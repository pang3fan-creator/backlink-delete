**日期：** 2026-06-06

## 一、技术问题

### 1. 数据库bug修复

**问题：** `bl.py` 的 import 索引错误
- 代码：`headers[4:]` → 应为 `headers[3:]`
- 影响：extractkeywords.com 列数据被漏掉
- 修复：已更正索引

**教训：** 脚本修改后要验证数据完整性，特别是涉及列索引的改动

### 2. 目录站点自动化障碍

**问题：** 高权重目录站点自动化提交困难
- 大多需要 Google/GitHub 登录
- 自动化浏览器被识别为"不安全"，OAuth 登录失败
- Cloudflare 拦截了多个站点

**结论：** 目录站点需主人手动处理

## 二、策略优化

### 3. 博客评论验证成功

**验证结果：**
- ✅ Website 字段外链正常工作
- ✅ 评论内容自然相关 → 通过审核
- ✅ 策略正确：只填 Website，不在正文插链接

**HTML渲染：**
```html
<a href="https://extractkeywords.com" rel="nofollow">Stefan M.</a>
```

### 4. "一站点三项目"原则

**错误做法：** 同时提交三个项目 → 太可疑
- 同一邮箱、同一名字、同一时间
- 容易被识别为垃圾评论

**正确做法：** 错开时间提交 → 更自然
- 发现站点 → 先提交一个项目
- 后续再补充其他项目

**当前模式：** "补作业"模式正确
- 主人之前提交了 heicpdf.to 和 tryschedule.com
- 素贞现在补充 extractkeywords.com

### 5. 外链本质认知

**博客评论外链属性：**
- 通常 `rel="nofollow"`
- 不传递 SEO 权重
- 作用：混脸熟、外链多样性

**Website 字段 vs 正文链接：**
| 维度 | Website 字段 | 正文链接 |
|------|-------------|----------|
| SEO属性 | nofollow | nofollow |
| 通过率 | 高 | 低 |
| 存活率 | 高 | 低 |
| 锚文本 | 无 | 有 |

**结论：** 效果相同，Website 字段更安全
