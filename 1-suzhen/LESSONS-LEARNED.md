## 关键教训

### ❌ 问题一：邮箱漏填

**问题**：早期提交时邮箱没填或填了临时邮箱
**影响**：无法收到审核通知，不知道是否被收录
**修复**：SOP 已更新，邮箱统一为 `pang3fan@gmail.com`

### ❌ 问题二：名称自己编

**问题**：项目名称自己编造（"Keyword Extractor" 等）
**影响**：不专业，可能被站长拒绝
**修复**：名称统一用域名主体：extractkeywords、tryschedule、heicpdf

### ❌ 问题三：博客评论不读文章

**问题**：博客评论没有阅读文章内容就硬插链接
**影响**：评论相关性差，容易被识别为垃圾评论
**修复**：SOP 已明确，博客评论必须先读文章再生成相关评论

### ❌ 问题四：Website 字段漏填（6月2日发现，6月3日验证）

**问题**：
- 6月2日主人发现评论提交没有填写 Website 字段（只写了评论，没留网址）
- 6月3日抽查了 3 个声称提交成功的站点，评论均未在页面找到（可能被 Akismet 拦截或未通过审核）

**影响**：外链白做，浪费时间和站点资源
**修复**：
1. 建立**双轨制记录**：数据库（长期）+ 日志文件（临时追溯）
2. 新增 `log_submission.py` 工具，记录每次提交的详细信息
3. 日志明确记录 Website 字段，主人可定期检查

## 工作哲学升级

> **素贞主导的自动化**：流程由素贞控制，步骤借助小工具辅助。
>
> - 需要理解的步骤（读文章、写评论）→ 素贞亲自做
> - 机械性步骤（记录数据库、写入日志）→ 调用脚本
> - 每个步骤要么用工具，要么手动操作，最终跑完整条流程

### 当前工具箱

| 工具 | 用途 |
|------|------|
| `bl.py` | 数据库记录、导出、统计 |
| `log_submission.py` | 日志文件记录 |
| `wp_comment.py` | 生成 WordPress 评论提交 JS 代码 |

## 成功站点特征

| 站点类型 | 成功率 | 特征 |
|---------|-------|------|
| **AI 工具目录** | 高 | 表单简洁，无验证码，3-5 字段 |
| **博客评论** | ~60% | WordPress 博客，有 URL 字段，审核宽松 |
| **传统目录** | 低 | 常有验证码、付费、登录门槛 |

## 失败原因分析

| 原因 | 占比 | 处理方式 |
|------|------|---------|
| 需登录 | ~20-30% | 跳过标记，主人手动处理 |
| 站点不可访问（404/503/重定向） | ~20% | 标记为失效 |
| Akismet 拦截 | 偶发 | 无法绕过，标记失败 |
| 评论已关闭 | 偶发 | 标记失效 |
| 表单提交异常 | ~10% | 尝试 JS 提交，不行则跳过 |

---

## 成功后策略

1. **先挑容易的** → 无需登录、评论区正常的站点先提交
2. **需登录的标记** → 留给主人手动处理
3. **需登录站点池** → 简单站点都提交完后，再研究处理方式
4. **日志定期检查** → 主人上服务器看日志，确认 Website 字段是否填写
